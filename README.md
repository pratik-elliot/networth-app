# Net Worth Ledger

A private, multi-currency (USD/INR) net-worth and account tracker: bank accounts, lockers,
real estate, automobiles, gold/silver/jewelry, investments, transactions, balance history,
nominees, KYC dates, dashboards, and reports — with a real backend and database, email-based
two-step login, and unrestricted data export.

This is a two-part project:
- **`server/`** — Node.js + Express API with a SQLite database (all your data lives here).
- **`client/`** — React (Vite) frontend that talks to the API.

Nothing here is deployed yet — you'll run/deploy both parts yourself using the steps below.
That's true of any real app like this: it needs to live somewhere with its own database and
its own domain, which requires an account with a hosting provider.

---

## 1. Run it locally first (recommended)

You'll need [Node.js](https://nodejs.org) 18+ installed.

### Backend
```bash
cd server
cp .env.example .env      # then open .env and set JWT_SECRET to any long random string
npm install
npm run dev
```
The API now runs at `http://localhost:4000`. Since SMTP isn't configured yet, login
verification codes will be **printed to this terminal window** instead of emailed —
that's expected for local testing.

### Frontend
In a second terminal:
```bash
cd client
npm install
npm run dev
```
Open `http://localhost:5173`, create an account, and check the **server terminal** for your
6-digit login code.

## 2. Setting up real email delivery for login codes

Open `server/.env` and fill in:
```
SMTP_HOST=smtp.yourprovider.com
SMTP_PORT=587
SMTP_USER=your-smtp-username
SMTP_PASS=your-smtp-password
SMTP_FROM="Net Worth Ledger <no-reply@yourdomain.com>"
```
Any SMTP provider works. Easy options to start with:
- **Gmail**: use an [App Password](https://myaccount.google.com/apppasswords) on a Gmail account, host `smtp.gmail.com`, port `587`.
- **SendGrid / Mailgun / Postmark**: free tiers exist for low volume; each gives you SMTP credentials directly in their dashboard.

Restart the server after editing `.env`.

## 3. Deploying so you can use it from your phone

This repo includes a `render.yaml` Blueprint that deploys the client and server together as a
**single Render Web Service**: the Express server serves the built React app as static files
and answers `/api/*` requests itself, so there's only one URL and no CORS to configure.

1. Push this project to a GitHub repo.
2. On [Render](https://render.com): New → Blueprint → connect the repo. Render reads
   `render.yaml` and creates the web service automatically (build command builds the client
   then installs server deps; start command runs `node server/src/index.js`).
3. In the service's Environment tab, fill in the SMTP_* variables (`SMTP_HOST`, `SMTP_USER`,
   `SMTP_PASS`, `SMTP_FROM`) so login codes get emailed instead of just printed to the logs.
   `JWT_SECRET` is auto-generated by the Blueprint.
4. Deploy. You'll get a single URL, e.g. `https://networth-app.onrender.com` — that's both
   your frontend and your API.

**Free plan caveat:** `render.yaml` defaults to Render's free instance type, which has no
persistent disk attached. That means the SQLite database and any uploaded images are wiped
every time the service redeploys or wakes up from idle sleep (free instances sleep after ~15
min of inactivity). That's fine for trying it out, but for data you actually want to keep,
upgrade the service to a paid plan, attach a disk (e.g. mounted at `/var/data`), and point the
`DB_PATH` and `UPLOAD_DIR` environment variables at that mount.

### Install it on your phone like an app
Once deployed, open the frontend URL in Safari (iOS) or Chrome (Android) and choose
**"Add to Home Screen"**. It'll launch full-screen with its own icon — no App Store needed.
This is a Progressive Web App (PWA); a basic manifest is already included in
`client/public/manifest.json` (add your own icon files there if you want a custom icon).

## 4. What's simulated vs. real here

- **Login security**: real — password + a genuinely emailed one-time code, backed by a real database, not a local-only passcode.
- **Data storage**: real — a SQLite database on your server, shared across every device you log in from.
- **Full history export, no record limits**: real — Reports → Download Full Data pulls everything, unpaginated.
- **Automatic value lookups** (gold/property/vehicle pricing from public sources): **not automated** — no backend service here calls external pricing APIs. The "Update Value" flow asks you to paste in the figure, date, and source URL after you look it up, fully editable later. Wiring up a real price-lookup service (e.g. a gold-price API, a VIN-decoding + valuation API) is a natural next step once this is live — happy to add it.
- **Google Drive / Dropbox sync**: **not included**. Your database *is* the persistent store now, which is more reliable than syncing files. If you specifically want a copy mirrored to Drive/Dropbox, that needs OAuth app credentials from Google/Dropbox — let me know if you want that added later.

    src/
      index.js        entry point

      routes/          auth, accounts, transactions, balances, images, export

    src/
      App.jsx
