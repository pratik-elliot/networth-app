# Net Worth Ledger

A private, multi-currency (USD/INR) net-worth and account tracker: bank accounts, lockers,
real estate, automobiles, gold/silver/jewelry, investments, transactions, balance history,
nominees, KYC dates, dashboards, and reports — with a real backend and database, email +
password login, and unrestricted data export.

This is a two-part project:
- **`server/`** — Node.js + Express API backed by MongoDB Atlas (all your data lives here).
- **`client/`** — React (Vite) frontend that talks to the API.

This is already deployed at **https://networth-app-dlqv.onrender.com**. The steps below also
let you run it locally, or deploy your own copy under a different account/domain.

---

## 1. Run it locally first (recommended)

You'll need [Node.js](https://nodejs.org) 18+ installed.

### Backend
```bash
cd server
cp .env.example .env      # set MONGODB_URI and JWT_SECRET
npm install
npm run dev
```
The API runs at `http://localhost:4000`. There is no native dependency to
compile, so this works on Windows, macOS and Linux alike.

### Frontend
In a second terminal:
```bash
cd client
npm install
npm run dev
```
Open `http://localhost:5173` and register an account. Login is a single step —
email + password — so you're straight in; no code to wait for.

---

## 2. Email delivery (currently only used for account-related notices, not login)

Two-step login (an emailed one-time code after your password) is **currently disabled** —
login is just email + password, guarded by IP-based rate limiting instead. `utils/mailer.js`
and the `otpCodes` collection are still in place, so it can be reinstated later by restoring
the OTP issue/verify routes in `server/src/routes/auth.js`.

If you do re-enable it, the working option on Render's free tier is **Resend's HTTP API**
(`RESEND_API_KEY` in `server/.env`, already wired up in `utils/mailer.js` and declared in
`render.yaml`) — it sends over HTTPS/443, which free Render instances don't block. Plain SMTP
(`SMTP_HOST`/`SMTP_PORT`/`SMTP_USER`/`SMTP_PASS`/`SMTP_FROM`) works too, but Render's free plan
blocks outbound ports 25/465/587, so that path needs a paid plan. With neither configured,
any mail `mailer.js` is asked to send is just printed to the server console.

## 3. Deploying so you can use it from your phone

This repo includes a `render.yaml` Blueprint that deploys the client and server together as a
**single Render Web Service**: the Express server serves the built React app as static files
and answers `/api/*` requests itself, so there's only one URL and no CORS to configure.

1. Push this project to a GitHub repo.
2. On [Render](https://render.com): New → Blueprint → connect the repo. Render reads
   `render.yaml` and creates the web service automatically (build command builds the client
   then installs server deps; start command runs `node server/src/index.js`).
3. In the service's Environment tab, set `MONGODB_URI` to your Atlas connection string
   (`mongodb+srv://...`). `JWT_SECRET` is auto-generated by the Blueprint. The `RESEND_API_KEY`
   / `SMTP_*` variables only matter if two-step login gets re-enabled (see section 2 above) —
   leave them blank otherwise.
4. Deploy. You'll get a single URL, e.g. `https://networth-app.onrender.com` — that's both
   your frontend and your API.

**Data persistence:** all data — accounts, transactions, balance logs and uploaded
files — lives in MongoDB Atlas, not on Render's disk, so it survives redeploys and
idle spin-down. Render's free plan needs no disk attached. Note Atlas' free tier
allows 512MB in total, which is why attachments are capped at 8MB each.

### Install it on your phone like an app
Once deployed, open the frontend URL in Safari (iOS) or Chrome (Android) and choose
**"Add to Home Screen"**. It'll launch full-screen with its own icon — no App Store needed.
This is a Progressive Web App (PWA); a basic manifest is already included in
`client/public/manifest.json` (add your own icon files there if you want a custom icon).

## 4. What's simulated vs. real here

- **Login security**: email + password against a real database, with bcrypt-hashed passwords and IP-based rate limiting (15 failed sign-in attempts per 15 minutes; successful logins aren't counted). The emailed one-time code is currently **disabled** — `utils/mailer.js` and the `otpCodes` collection are still in place, so two-step login can be restored by reinstating the OTP issue/verify routes in `routes/auth.js`. Until then your password is the only credential, so make it a strong, unique one.
- **Data storage**: real — a MongoDB Atlas database, shared across every device you log in from.
- **Full history export, no record limits**: real — Reports → Download Full Data pulls everything, unpaginated.
- **File attachments**: real — each account accepts images, PDF, CSV, Excel (.xls/.xlsx), Word (.doc/.docx) and .txt files, up to 8MB each and 10 at a time (Atlas' free tier allows 512MB in total, hence the smaller per-file cap than the old disk-based limit). Images render as thumbnails; documents show as a labelled tile you can click to open or download. Note these are *stored as attachments* — to turn a statement into transactions, use Import statement instead (below).
- **Statement import**: real — upload a PDF, CSV or Excel bank statement to an account and its
  rows are extracted into transactions. Text-layer PDFs only; a scanned statement is detected and
  reported rather than guessed at. Extraction uses a model on OpenRouter, and every request demands
  a zero-data-retention provider, failing rather than sending your statement to one that would
  retain it. Nothing is saved until you review an editable table and confirm; rows matching
  existing transactions are flagged and unticked so re-importing an overlapping statement cannot
  double-count. Requires `OPENROUTER_API_KEY` — the feature hides itself when it is unset.
- **Automatic value lookups** (gold/property/vehicle pricing from public sources): **not automated** — no backend service here calls external pricing APIs. The "Update Value" flow asks you to paste in the figure, date, and source URL after you look it up, fully editable later. Wiring up a real price-lookup service (e.g. a gold-price API, a VIN-decoding + valuation API) is a natural next step once this is live — happy to add it.
- **Google Drive / Dropbox sync**: **not included**. Your database *is* the persistent store now, which is more reliable than syncing files. If you specifically want a copy mirrored to Drive/Dropbox, that needs OAuth app credentials from Google/Dropbox — let me know if you want that added later.

## 5. Project structure
```
networth-app/
  server/            Express API
    src/
      index.js        entry point
      db.js            MongoDB connection + collection accessors
      routes/          auth, accounts, transactions, balances, attachments, exportData
      middleware/      auth (JWT), rateLimit (login + general API limits)
      services/        accountShape (API <-> storage document mapping)
      utils/           asyncHandler, mailer (OTP email sending, currently unused)
    test/              node:test suites, one per route/module
    .env.example
  client/            React (Vite) frontend
    src/
      App.jsx
      api.js           API client
      theme.js          shared constants/helpers
      pages/           Login, Dashboard, AccountsList, AccountDetail, Reports, Settings
      components/      AccountForm, Attachment (auth'd file preview/download), SmallForms, ui.jsx
      lib/             attachmentBlobCache (caches fetched attachment bytes as blob URLs)
    public/manifest.json
  render.yaml          Render Blueprint (single Web Service, builds client + runs server)
  .node-version        pins the Node version Render builds with
```
